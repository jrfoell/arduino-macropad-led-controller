# Balance Setting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Global Balance setting that dims the top or bottom outdoor strip (never brightens), with live preview, persisted on both boards.

**Architecture:** MacroPad folds Brightness × Balance into per-strip percents (shared, tested math) and sends those; the QT Py renders each strip at its own percent with no notion of balance.

**Tech Stack:** Arduino C++ (arduino-pico), `arduino-cli --profile`, `g++` tests for `MacropadShared`.

**Spec:** `docs/superpowers/specs/2026-11-25-balance-design.md`

## Global Constraints

- Balance 0-100, default 50, 5% per detent; 0 = top strip off, 100 = bottom strip off; never brightens.
- `topScale = b < 50 ? b*2 : 100`, `bottomScale = b > 50 ? (100-b)*2 : 100`; strip % = `brightness * scale / 100`.
- I2C protocol change: both boards flash together.
- Header-only, underscore filenames, `#pragma once`, top-of-file API comment (CLAUDE.md conventions).

## Review Focus

- Old saved settings on either board (pre-Balance magic) must load with balance 50 and current brightness — not garbage.
- Balance at 0 must render the top strip truly black (0,0,0), including after a QT Py power cycle with no MacroPad.
- Test Pattern must ignore Balance (all LEDs lit).
- Brightness knob preview while balance ≠ 50 must keep the balance split, not reset to even.
- Top-menu wrap with 5 items; entering Presets/Test Pattern via their new indexes.
